# whisper Meeting Note

Kotlin / Jetpack Compose / Material 3. v0.7.0, Android 8.0(API 26) 이상, arm64-v8a 및 x86_64.

## 공개 저장소와 API 키 관리

Groq와 Gemini API 키는 저장소나 빌드 설정에 넣지 않고, 설치한 앱의 **설정**에서 각자 등록한다. 키는 Android Keystore로 암호화하고 앱 내부 설정에 암호문과 IV만 저장한다. 앱 백업은 비활성화되어 있으며 기기 이전에서도 해당 설정을 제외한다.

`local.properties`, `.env` 계열, 인증/서명 키 파일, 빌드 결과물, 실행 로그, 에이전트 첨부 사진은 `.gitignore`로 제외한다. 개인 음성·전사·회의록은 저장소에 넣지 않는다. `app/src/androidTest/assets`의 음성은 공개된 공식 예제로 만든 테스트 자료이며 출처와 변환 방법은 [third_party/README.md](third_party/README.md)에 기록했다.

커밋 전에는 `git diff --cached`와 `git status --short`로 업로드 대상을 확인하고, Gitleaks 등의 비밀정보 검사 도구로 점검한다. `.gitignore`는 이미 추적 중인 파일이나 소스에 직접 적은 키를 보호하지 않으므로, 실제 키를 발견하면 공개 전에 제거해야 한다. 이미 노출된 키는 폐기하고 재발급한다.

## v0.7.0 Gemini 회의록 · 요약

화자 분석 결과를 바탕으로 회의록과 요약을 각각 생성한다. 기본 모델은 `gemini-3.8-flash`다.

1. **설정 → 회의록 · 요약 AI → Gemini 키 저장**에서 개인 Gemini API 키를 등록한다. Groq 키와 별도로 Android Keystore를 사용해 암호화하며 키 입력 화면 캡처는 차단한다.
2. **AI 모델 ID**, **회의록 프롬프트**, **요약 프롬프트**를 수정한 뒤 **AI 설정 저장**을 누른다. **AI 기본값 불러오기**는 편집값을 초기화하며 저장 전까지 실제 설정을 바꾸지 않는다. 설정은 앱을 재실행하거나 최근 작업을 삭제해도 유지된다.
3. 화자 분석을 완료한 결과 화면에서 **회의록 / 요약** 탭을 선택하고 **작성**을 누른다. 수정된 화자 이름과 배정, 발언 ID·시작/종료 시각·내용, 회의 제목을 Google에 전송한다. 이 요청에는 음성 파일을 포함하지 않는다.
4. 생성된 내용은 해당 탭에서 읽거나 복사할 수 있고 최근 작업과 함께 저장된다. 다시 작성 중 실패·취소되면 이전 결과를 유지한다. 화자 이름·배정이나 제목을 변경하면 기존 결과가 이전 자료 기준임을 표시한다. 모델·프롬프트 설정 변경은 다음 생성부터 적용된다.

기본 프롬프트는 제안과 확정 사항을 구분하고, 결정/할 일에 근거 발언 ID와 시각을 붙이며, 원문에 없는 담당자·기한을 만들지 않도록 요청한다. 모델이 만든 문서의 사실성이나 근거 정확성을 프로그램이 검증하는 것은 아니므로 원문 확인이 필요하다. 화자 분석 결과가 없으면 생성을 비활성화한다. 입력을 임의로 잘라 보내지 않으며 모델의 입력 한도를 넘으면 오류를 안내한다.

- `TextGenerationProvider` / `TextGenerationRequest`: 제공자 독립 인터페이스. `MeetingAiService`는 제공자 레지스트리에서 어댑터를 선택하고 회의록/요약 프롬프트를 전달한다.
- `GeminiTextProvider`: `POST /v1beta/models/{model}:generateContent`, `x-goog-api-key`, `systemInstruction`과 입력 자료 분리. HTTP 오류 본문은 표시/로깅하지 않으며 코루틴 취소 시 OkHttp 요청도 취소한다. 차단·빈 응답·미완료 응답은 성공 결과로 저장하지 않는다.
- 현재 구현된 제공자는 Gemini다. 향후 OpenAI 등을 연결할 때 `TextGenerationProvider` 구현을 추가하고 레지스트리, 설정 제공자 선택 및 해당 제공자의 키 저장소를 연결한다. 회의 자료 구성·화면·결과 저장 계약은 재사용한다.
- `MeetingStore` JSON version 1의 선택 필드 `minutes` / `summary`에 본문, 제공자·모델, 생성 시각, 입력 SHA-256을 저장한다. 기존 저장본과 호환되며 원문 변경 여부를 해시로 판별한다.
- 모델 호출에는 외부 검색 도구나 자동 재시도를 사용하지 않는다. 실제 API 사용량은 사용자 Gemini 프로젝트에 청구될 수 있다.

API 계약 참고: [Gemini generateContent](https://ai.google.dev/api/generate-content).

검증: `assembleDebug testDebugUnitTest lintDebug assembleDebugAndroidTest` 통과. 단위 테스트 63개(새 AI 테스트 7개), Android 14 x86_64 에뮬레이터 계측 테스트 22개(새 AI 테스트 4개 포함) 통과. 모델/프롬프트 전달, 제공자 대체, HTTP 오류·응답 차단·미완료·취소, 설정/문서 복원, 기존 전사·화자 화면 회귀를 확인했다. lint 오류 0개·경고 14개다. 화면 검사용 2개 테스트를 추가 실행하고 최종 APK versionName 0.7.0/versionCode 10 설치 및 COLD 실행도 확인했다. 화면 증거 `build/verification/meeting-ai-minutes.png`, `meeting-ai-settings.png`는 예시 데이터와 설정 컴포넌트 테스트다. 실제 Gemini API 키로 서버를 호출한 결과 품질·과금·모델 접근 권한과 ARM64 실기기는 미검증이다.

## v0.6.1 저장한 음성의 업로드 확장자 수정

최근 작업 저장 기능은 원본 바이트를 `audio-UUID.bin`으로 보관한다. Groq 업로드가 이 내부 파일명을 multipart filename에 그대로 사용해, 지원하던 M4A/MP3 파일도 원래 확장자를 잃는 회귀를 수정했다. 업로드명은 선택 당시 이름의 확장자로 만든 `audio.m4a` 등의 고정 이름을 사용한다. 개인 파일명은 전송하지 않으며 파일 내용과 MIME은 그대로 유지한다. 이미 저장된 작업에도 적용되므로 저장본 삭제나 재선택은 필요하지 않다.

수정 전 `.bin` 업로드를 회귀 테스트로 재현했고, 수정 후 지원 확장자 9종(대문자 원본 이름 포함)의 multipart 파일명 및 원본 바이트 보존을 확인했다. 최종 빌드·단위 테스트 37개·lint 통과. 실제 사용자 파일을 이용한 Groq 서버 전사 및 ARM64 실기기는 이번 수정에서 검증하지 않았다.

## v0.6.0 블룸 대화 시안 일치 및 기능 연결

원본 시안의 파형 헤더, 단계 이동, 제목·메타데이터, 파일명 옆 완료 배지, 결과 탭, 화자·시간 행, 좌우 말풍선과 고정 하단 버튼을 기준으로 화면을 다시 구성했다. 글자 크기·줄 간격·색상·모서리·여백을 시안 수치에 맞췄으며 민트 대화 런처 아이콘은 유지한다. 실제 Android 글꼴과 화면 높이에 따라 줄바꿈 및 스크롤 범위는 달라질 수 있다.

- 파일 선택 / 분석 중 / 전사 결과를 실제 작업 상태에 맞춰 이동한다. 전사가 먼저 끝나면 화자 분석 중에도 전체 글을 보고 복사할 수 있다.
- 회의 제목을 눌러 파일명과 별도로 수정·저장한다. 파일을 가져온 날짜와 실제 음성 길이를 표시한다. 구버전 저장본은 원본이 있으면 길이를 읽으며, 알 수 없는 날짜를 임의로 만들지 않는다.
- 전사·화자 구분·발화 연결의 실제 상태와 화자 분석 진행률, 완료된 분석 구간 수를 표시한다. 실패·취소 상태를 구분하고 완료된 전사를 보존한다.
- 화자 선택·이름 변경, 참석 인원 변경 후 재분석, 설정, 새 파일 교체를 하단 시트로 연결했다. JSON version 1에 선택적 메타데이터를 추가해 기존 저장본과 호환한다.

검증: 최종 APK 빌드, 단위 테스트 36개 통과. lint 오류 0개·경고 13개. Android 14 x86_64 에뮬레이터 UI 테스트 11개 및 메타데이터/실제 음성 분석 테스트 2개 통과. 제목 수정, 단계 이동, 화자 편집 저장, 1.5배 글꼴, 날짜·길이 저장/복원, 구버전 JSON 호환, 실제 native 분석의 구간 진행률을 확인했다. 최종 APK 설치 버전과 MainActivity COLD 실행도 확인했다. 이번 변경의 실제 Groq API 요청 및 ARM64 실기기 검증은 수행하지 않았다.

## 실행

APK 파일명은 빌드 시 `whisper-meeting-note-v{versionName}-{versionCode}-{빌드유형}.apk`로 자동 생성된다. 예: `app/build/outputs/apk/debug/whisper-meeting-note-v0.7.0-10-debug.apk`. 아래 이전 버전 기록의 `app-debug.apk`는 당시 파일명이다.

1. Android Studio에서 이 폴더를 열고 Gradle Sync를 실행한다. JDK 17 또는 21, Android SDK 35가 필요하다.
2. 필요하면 `local.properties`에 로컬 SDK 경로를 설정한다. API 키는 이 파일에도 넣지 않는다.
3. 앱 실행 → **설정** → 본인의 Groq API 키 입력 → **키 저장**.
4. **음성 파일 선택** → 시스템 선택기에서 M4A/MP3 등의 파일 선택 → **전사 시작하기**.
5. **화자 구분**을 켜면 화자별 발화를 볼 수 있다. 기본 화자 수는 자동이며 2·3·4명으로 지정할 수 있다. 결과 탭에서 화자별·전체 글·시간별 보기를 전환하고 하단 버튼으로 복사한다.
6. 각 말풍선의 **화자 이름**을 눌러 해당 발화를 다른/새 화자 또는 화자 불명으로 배정한다. 이름 변경은 같은 화자의 모든 발화 및 복사 결과에 반영된다. 수정 내용은 최근 작업 한 건에 자동 저장되며 앱 재실행 시 복원된다.
7. 결과 화면의 **화자 분석**을 누르면 참석 인원과 초기화 안내를 확인하고 **다시 분석**을 실행할 수 있다.
8. 결과 화면의 회의 제목을 누르면 별도 제목을 수정할 수 있다. 원본 파일명은 유지된다.

```powershell
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
# 연결된 Android 기기/에뮬레이터에서 실제 코덱 및 모델 테스트
.\gradlew.bat connectedDebugAndroidTest
```

APK: `app/build/outputs/apk/debug/app-debug.apk`

## API 계약

- POST `https://api.groq.com/openai/v1/audio/transcriptions`
- Bearer 인증, multipart/form-data: `file`, `model=whisper-large-v3-turbo`, `language=ko`, `response_format=verbose_json`, `timestamp_granularities[]=segment`.
- 화자 분리 사용 시 동일 요청에 `timestamp_granularities[]=word`를 추가한다. 화자 분리 OFF에서는 기존 요청을 유지한다.
- 무료 플랜 25MB 한도에 맞춰 보수적으로 **25,000,000바이트**까지 허용한다.
- 지원 확장자: flac, mp3, mp4, mpeg, mpga, m4a, ogg, wav, webm. 파일 선택기는 공급자별 MIME 차이를 고려해 전체 파일을 표시하고 앱에서 검증한다.
- [Groq 공식 Speech to Text 문서](https://console.groq.com/docs/speech-to-text), [공식 API Reference](https://console.groq.com/docs/api-reference)를 기준으로 요청 형식을 확인했다.

- `MainActivity`: Compose 화면, 시스템 OpenDocument 선택기, 클립보드 복사.
- `TranscriptionViewModel`: StateFlow, viewModelScope, IO dispatcher, 취소 및 상태 처리. 화면 회전 시 작업과 결과를 유지한다.
- `AudioFiles`: content URI를 파일 경로로 변환하지 않고 ContentResolver로 읽는다. 크기 메타데이터와 실제 스트림 양쪽에서 제한을 검사한다. 앱 내부 캐시로 복사하므로 영구 URI 권한이나 광범위 저장소 권한이 필요하지 않다.
- `GroqApi`: OkHttp 비동기 요청과 coroutine 취소 연동, HTTP 오류별 사용자 안내. 자동 재시도·리디렉션·민감한 요청 로깅을 사용하지 않는다.
- `ApiKeyStore`: Android Keystore의 AES/GCM 키로 API 키를 암호화한다. 암호문과 IV만 private SharedPreferences에 저장하고 앱 백업을 끈다. 키 입력 화면 캡처를 차단한다. 실제 키는 소스/빌드 설정에 없다.
- 전사 시 음성 파일은 Groq에 전송된다. 최근 작업의 전사·단어/구간 시간·화자 이름과 수동 배정은 앱 내부 파일에 저장되고 프로세스 재시작 시 복원된다. 복사한 텍스트는 시스템 클립보드에 남을 수 있다.
- 재분석용 원본 음성과 JSON은 noBackupFilesDir/current-meeting에 보관한다. 새 파일 저장 성공 시 이전 음성을 정리하며, 설정에서 저장된 작업을 삭제할 수 있다. 원래 선택한 외부 파일은 건드리지 않는다. 임시 업로드 캐시는 복사 후 정리하고 PCM은 매 분석 종료 시 삭제한다.
- 녹음, DB, 로그인, 백엔드는 포함하지 않는다. v0.7.0부터 회의록·요약은 Gemini API를 사용한다.

## 화자 분리 파이프라인

`content URI → 내부 원본 캐시 → [Groq 전사 || PCM 디코딩 → sherpa 화자 분석] → 단어/화자 시간 매칭`

- sherpa-onnx **v1.13.8**, pyannote segmentation 3.0 INT8 + NeMo TitaNet Small, CPU 2 threads. 라이브러리/모델을 APK에 포함하고 빌드 시 SHA-256을 검사한다. 원본 URL·해시·라이선스는 `third_party/README.md`에 기록했다.
- `AudioDecoder`: 첫 오디오 트랙을 MediaExtractor/MediaCodec으로 디코딩한다. PCM16/float를 모노로 변환하고 저역통과 필터 및 연속 위상 resampler로 16kHz를 만든다. 타임스탬프 공백은 무음으로 보존한다. 필터 지연은 44.1/48kHz에서 약 1ms 미만이다.
- **10분 제한을 제거했다.** 디코딩한 16kHz float PCM은 캐시에 저장하고 `DecodedAudio`에서 분석할 구간만 읽는다. 기본 core 120초 + 앞뒤 context 각 2초이므로 한 번에 읽는 오디오는 최대 124초다. context를 포함해 분석한 뒤 core 범위로 잘라 경계 중복을 방지한다. 녹음 전체에 대한 하나의 거대한 FloatArray를 만들지 않는다.
- PCM 저장 공간은 녹음 1시간당 약 230MB다. 디코딩 시작 시 여유 공간에서 64MB를 제외한 만큼만 사용하며, 실제 쓰기 실패도 기존 전사 보존 오류 경로로 처리한다. 고정된 전체 시간 제한 대신 디코더 60초 무응답 감지, 화자 후보 1024개 상한을 둔다. 원본 업로드의 **25MB 제한은 그대로**다.
- `SpeakerDiarizer`: 각 창에서 화자 수를 자동 추정하고, 겹말을 제외한 대표 발화 최대 15초로 TitaNet 임베딩을 별도 추출한다. 0.3초 미만은 화자 불명으로 남긴다. 2초 미만 후보는 새 화자를 만들지 않고, 충분한 발화로 만든 군집에 유사도와 2순위 점수 차이가 충족될 때만 연결한다. 한 창에 참석자 전원이 등장한다는 가정을 하지 않는다.
- `GlobalSpeakers`: 전체 창의 정규화된 임베딩을 cosine similarity 기반 centroid clustering으로 묶는다. 자동 모드 cosine threshold는 0.5다(지역 모델의 cosine distance 0.5와 수치 기준을 맞췄지만 군집 알고리즘은 다르다). 자동 모드에서는 0.5초 이상 겹치는 지역 후보를 병합하지 않는다. 수동 화자 수는 전체 녹음의 최대 군집 수이며, 모델의 겹말 판정보다 사용자의 지정 수를 우선한다. 짧은 후보 연결은 cosine 0.5 이상, 2순위와의 차이 0.1 이상일 때만 허용하며 군집 중심을 바꾸지 않는다. 이 기준은 한국어 통화에 최적화된 보장값이 아니다. 같은 창에서 분리된 후보라도 겹말 근거가 없으면 같은 사람으로 재결합할 수 있다. 결과 화자 ID는 전체 녹음 기준으로 한 번 정하고 첫 등장 순서로 표시한다.
- `TranscriptionPipeline`: Groq와 로컬 분석을 병행한다. Groq 결과를 먼저 표시하며, 로컬 디코더/모델/길이 제한 오류가 나도 성공한 전체 전사는 유지한다. 원본 파일은 앱 재실행 후에도 화자 단독 재분석을 할 수 있도록 보관한다.
- `SpeakerAlignment`: 단어와 화자 구간의 겹치는 시간을 계산한다. 50% 이상 커버되고 경쟁 화자 커버가 25% 미만인 경우에만 배정한다. 겹말·애매한 경계·무음은 `화자 불명`으로 표시한다. 같은 화자의 연속 단어를 묶되 1초 이상의 공백은 별도 발화로 둔다. 원본 전체 텍스트와 원본 segment도 그대로 표시한다.
- 화자 번호는 녹음 전체에 걸쳐 연결하지만, 다른 파일에서도 동일인을 식별하는 기능은 아니다. 지역 clustering threshold는 0.5이며, 잡음/짧은 발화/음색 변화 때문에 오분류 가능성이 있다. 한국어 회의 품질 평가는 별도로 필요하다.
- **취소 제한:** v1.13.8 native 구현은 callback 반환값으로 중단되지 않는다. 현재 창의 native 처리가 끝나면 취소를 확인하고 다음 창을 시작하지 않는다. 진행 중 native 객체나 입력 파일을 먼저 해제하지 않는다. UI 진행률은 구간 분석과 전역 병합 단계의 근사 진행률이다.
- 처리 중 화면이 꺼지지 않도록 하며, 앱을 열어둔 상태로 사용한다. 백그라운드 서비스나 프로세스 종료 후 재개 기능은 포함하지 않는다.
- 모델이 실패하거나 단어 시간이 없으면 화자 결과 대신 안내와 기존 전사를 표시한다. Android 디코더가 지원하지 않는 형식도 Groq 전사는 계속 가능하다.

## v0.3.1 화자 과분할 수정 (2026-10-22)

자동 분석에서 2인 통화가 다수 화자로 분리된 사용자 보고에 대응했다. 2초 미만의 대표 음성은 독립 화자 군집을 생성하지 않으며, 기존 군집에 충분한 유사도/점수 차이가 있을 때만 연결한다. 0.3~1초 음성도 연결 후보로 사용할 수 있다. 전역 자동 병합 cosine 기준을 0.65에서 0.5로 조정했다. 수동 인원 지정은 겹말 판정 때문에 지정 수를 초과하던 문제를 수정했다. 근거 없는 화자 배정은 하지 않으므로 화자 불명이 완전히 사라지는 것은 아니다.

`assembleDebug testDebugUnitTest lintDebug connectedDebugAndroidTest` 성공. 단위 테스트 31개, Android 14 x86_64 계측 테스트 6개 통과. 367초 합성 2인 통화 대역폭 자료는 자동/2명 모두 화자 2명, 분석된 발화 시간 기준 90% 초과 배정을 확인했다(단어 매칭 정확도 수치가 아님). 기존 682초 자료의 자동/4명 모드 구간 간 번호 유지도 통과했다.

사용자가 문제를 보고한 실제 6분 한국어 통화는 제공되지 않아 재현 및 정확도 비교를 수행하지 못했다. 자동 모드의 과분할을 완전히 해결했다고 보장하지 않는다. 인원을 아는 통화는 2명 지정 사용을 권장한다. Groq 실제 API 호출과 ARM64 실기기 검증은 이번 수정에서 수행하지 않았다.

## v0.3.2 화자 단독 재분석 및 버전 정보

전사 완료 후 화자 수를 선택하고 `화자만 다시 분석`을 누르면 Groq 업로드/전사를 호출하지 않고 로컬 분석만 다시 수행한다. 최초 전사는 화자 분리 스위치와 관계없이 단어별 시간을 요청하므로 나중에 화자 분석을 추가할 수 있다. 서버가 단어별 시간을 반환하지 않으면 재분석 버튼을 비활성화한다. API 키를 삭제한 상태에서도 현재 전사에 대한 화자 단독 분석은 가능하다.

기존 텍스트와 타임스탬프는 그대로 유지한다. 성공하면 화자별 발화만 교체하고 이름/수동 배정은 초기화한다. 실패/취소 시에는 기존 화자 결과도 유지한다. 앱 종료 후 전사 복원 기능은 없으며 새 파일 선택 시 현재 결과가 초기화된다. 설정에 빌드의 versionName/versionCode를 표시한다.

v0.3.2 검증: 최종 APK 빌드, 단위 테스트 33개, lint 통과. Android 14 에뮬레이터에서 설정의 실제 빌드 버전 표시 및 화자 편집 UI 테스트 3개 통과. 단독 재분석의 기존 전사 불변성과 실패/취소 시 기존 결과 보존을 단위 테스트로 확인했다. 실제 Groq 전사 완료 → 인원 변경 → 화자 단독 재분석의 전체 기기 흐름은 이번 변경에서 실음성/API 키로 검증하지 않았다.

## v0.4.0 최근 작업 자동 저장

DB 없이 최근 한 건을 `MeetingStore`에 저장한다. 원본 파일은 새 이름으로 복사하고 JSON은 Android AtomicFile로 교체한 뒤 이전 원본을 정리한다. 완료된 전사는 화자 분석을 기다리지 않고 저장하며, 화자 결과/이름/수동 배정도 저장한다. 저장 실패는 화면에 알리고 기존 저장본을 유지한다. 원본이 유실되어도 전사와 화자 정보는 복원하되 재분석은 비활성화한다.

앱 시작 시 복원하며 API 키 로딩 실패와 독립적으로 처리한다. 이름/배정 수정은 하나의 저장 작업으로 반영한다. 새 파일 선택 전 최근 작업 교체 안내, 설정의 저장된 전사/음성 삭제 확인을 추가했다. 여러 회의 기록 목록은 포함하지 않는다. 앱 삭제/데이터 삭제 시 저장 내용도 삭제된다. 중단된 전사/분석을 자동 재개하는 기능은 아니다. 구버전에서 앱 종료로 이미 사라진 메모리 결과는 복구할 수 없다.

저장 구현 참고: https://developer.android.com/reference/android/util/AtomicFile
